Interacting with gRPC

A gRPC endpoint is available on the public Sentinel nodes, so you can start interacting with the chain right away. The public endpoint is served over TLS on port 443:

grpcurl fullgrpc-sentinel.busurnode.com:443 list
caution

The older grpc.sentinel.co:9090 address no longer accepts connections. Port 9090 is closed, and requests to grpc.sentinel.co are answered with an HTTP redirect that gRPC clients do not follow.

Enabling gRPC on a node​

If you are running your own node, enable gRPC by editing ~/.sentinelhub/config/app.toml:

  • grpc.enable = true|false field defines if the gRPC server should be enabled. Defaults to true.
  • grpc.address = {string} field defines the address (really, the port, since the host should be kept at 0.0.0.0) the server should bind to. Defaults to 0.0.0.0:9090.

Grpc endpoints​

An overview of all gRPC endpoints shipped with Sentinel is available in the Sentinel Protobuf documentation. The Cosmos SDK publishes its own Protobuf documentation.

On hub v12 the Sentinel query services are version-namespaced: node, session and subscription are served at v3, and deposit, lease, oracle and swap at v1. The full live list is on the gRPCurl page.

note

The plan v3 and provider v3 query services are registered on the gRPC server but not on the REST gateway, so they can only be reached over gRPC.

You can send requests to the gRPC server using a gRPC client such as grpcurl or from Buf Studio.

Since the code generation library largely depends on your own tech stack, we will only present three alternatives:

Frontend SDK Libraries & Utilities

grpcurl
Ideal for generic debugging and testing
Buf Studio
An interactive web UI for all the gRPC and Protobuf services
gRPC Go
gRPC inside a Go program

Generating the Protobuf code​

The hub generates its own Go bindings with buf. From a checkout of sentinel-official/hub:

make tools     # installs buf and the protoc plugins
make proto-gen
