gRPCurl

grpcurl is like curl but for gRPC. It is also available as a Go library, but we will use it only as a CLI command for debugging and testing purposes. Follow the instructions in the previous link to install it.

Choosing an endpoint​

The public gRPC endpoint is served over TLS on port 443, so no -plaintext flag is needed:

grpcurl fullgrpc-sentinel.busurnode.com:443 list
caution

The older grpc.sentinel.co:9090 address no longer accepts connections. Port 9090 is closed and requests to grpc.sentinel.co are answered with an HTTP redirect that gRPC clients do not follow.

If you are running your own node, use its address with -plaintext:

grpcurl -plaintext localhost:9090 list

This is called reflection: a Protobuf endpoint that returns a description of all available endpoints. Each entry is a different Protobuf service, and each service exposes multiple RPC methods you can query against.

info

Sentinel query services are version-namespaced. On hub v12, node, session and subscription are served at v3, and deposit, lease, oracle and swap at v1. The v1 and v2 services from earlier hub releases have been removed, with the two partial exceptions noted below.

To get a description of a service, run:

grpcurl \
    fullgrpc-sentinel.busurnode.com:443 \
    describe <grpc_service>

sentinel.subscription.v2.QueryService

Retained for backwards compatibility, but only QueryAllocation and QueryAllocations are implemented. Every other method on this service returns Unimplemented; use sentinel.subscription.v3.QueryService instead.

The payout methods have no replacement. In hub v12 the v2 payout records were migrated into the lease module, where the payout schedule is a property of a lease rather than a separately queryable record — query sentinel.lease.v1.QueryService instead.

Making a query​

grpcurl \
    -d '{"status":"STATUS_ACTIVE","pagination":{"limit":"5"}}' \
    fullgrpc-sentinel.busurnode.com:443 \
    sentinel.node.v3.QueryService/QueryNodes

Query for historical state using grpcurl​

You may also query for historical data by passing some gRPC metadata to the query: the x-cosmos-block-height metadata should contain the block to query.

grpcurl \
    -H "x-cosmos-block-height: 30000000" \
    -d '{"address":"sent1uddk4mfqq3uyu2yzhym8spheqatqs30fzh5tmr"}' \
    fullgrpc-sentinel.busurnode.com:443 \
    cosmos.bank.v1beta1.Query/AllBalances

Assuming the state at that block has not yet been pruned by the node, this query should return a non-empty response.
